How this was built

RigReady is written with AI coding agents. This page says how, so you can decide for yourself what that means to you.

Who made it

RigReady is a side project by Mark Cheli, a software engineer by profession for more than ten years, built for his own flight and racing rig and shared because other people have the same problem.

The code, the tests, the manual and this website were written by AI coding agents (Anthropic's Claude, in Claude Code), working from his direction. Mark decided what the product is and what it must and must not do (written down in docs/PRODUCT.md), set the safety rules, reviewed the results and the screenshots, tested it on his own PC, and decides what is released. He did not write the code by hand, and not every line has been read by a person.

How the work was checked

Care went into how the work was checked, because a computer full of games, settings and hardware is not a place to be careless. The methods:

  • Every feature is a written requirement with its acceptance criteria, in the requirements ledger. It counts as done only with a test of the real code and, for anything on screen, a screenshot from a test run. {{LEDGER_DONE}} of {{LEDGER_TOTAL}} are done today.
  • About 1,800 unit tests, and about 240 scenario tests that start the real app on a recorded copy of a rig with something changed ("pedals unplugged", "a screen rotated") and use it as a person would. Both run on a clean Windows machine in GitHub Actions for every change.
  • Safety rules the tests enforce across the whole code: any file outside RigReady's own folder is backed up before it is changed and the change can be undone; programs are never started from a command line built out of text; no message may claim success for something that did not happen.
  • A security review of the whole app, with what was found fixed and tested, and a security page that says what it touches.

None of this makes it free of mistakes. It is how they are kept small and found early.

What it was tested on

One rig: a Samsung 49-inch ultrawide, three small USB screens used for aircraft displays, a Dell desk monitor, WinWing devices (joystick, throttle, three display frames, UFC, ICP and cockpit panels), Thrustmaster TPR pedals, a Virpil control panel, a Stream Deck, TrackIR 5 and a Fanatec Podium DD2 wheel base, with DCS World, iRacing, Le Mans Ultimate, BeamNG.drive, Microsoft Flight Simulator 2024 and the Assetto Corsa games installed.

On that PC, tests read the real devices, monitors, audio and controllers, and changed and restored the real monitor layout and audio devices. The automated tests changed game files (bindings, the DCS screen setup, backups and restores, the iRacing repair) only on copies of that rig's files. On the rig itself, with its owner there, RigReady also changed the live files: a DCS binding, the DCS screen setup, a line in DCS's Export.lua, and iRacing button and key bindings. Each was then used in its game, and Undo put the DCS and iRacing binding files back byte for byte.

It has been used on one rig, so reports from other hardware help most, through the hardware report form.
