# Security review, November 2026

A review of the whole application before 2.0.0: the supply chain, the Electron windows, what the app does on the PC, what leaves it, and how an update reaches users. Done by reading the code and, where a claim needed it, by running the code (each such run is named below). `SECURITY.md` is the public summary; `docs/manual/app/security.md` is the page for users; `docs/RELEASING.md`, "Security fixes", is the runbook.

Severity is for this app's situation: a per-user desktop program, no server, no account, no elevation. "High" would be code running on someone's PC without their action; nothing found reached that. "Medium" is something a file from someone else could do with one ordinary action (importing it, restoring it). "Low" is a crash or a weakness that needs local access the attacker would already have. "Info" is a deliberate choice, recorded so it is not mistaken for an oversight.

| 1 | Untrusted input | YAML from a `.rigready` file, a backup or a setup file was loaded with no limit on aliases. A 520-byte `profile.yaml` of nine nested alias levels stands for a billion strings; js-yaml loads it in 2 ms, but the import writes the setup out again with `noRefs`, which expands it (measured: 7 levels, 393 bytes in, 197 MB out in 6.7 s; 9 levels would be about 20 GB). | 2 | Untrusted input | A backup opened from elsewhere (Backups > Open file) could name `{APPDATA}/Microsoft/Windows/Start Menu/Programs/Startup` as an item's folder. Restore checks that each file stays inside its item's folder, but not where that folder is. A `.url` file was not in the list of "files that run something", so it was ticked by default; at the next sign-in Windows would open it, and a `file://` address in it starts a program. | Medium | Fixed: a restore never writes into the Start menu, its Startup folder or `%LOCALAPPDATA%\Microsoft\WindowsApps`; `.url`, `.pif`, `.scf`, `.appref-ms`, `.application`, `.msc`, `.msp`, `.vb`, `.ws`, `.wsh`, `.psd1`, `.ps1xml`, `.xll` join the program list (never shared, flagged and not pre-ticked in a restore). | `src/core/paths.ts:58` (`startsByItself`), `src/features/backup/core/restore.ts:244`, `src/core/credentials.ts:101`; test `src/features/backup/core/backup.test.ts` ("never writes into the Startup folder") |

## Not covered

- No penetration test, fuzzing campaign or third-party audit. The archive, YAML and Lua parsers were tried with hostile inputs written for this review, not with a fuzzer.
- The DirectInput sidecar (`python/input_server.py`) was read, not tested: it reads devices and writes JSON lines to its own pipe, takes no input from files, and is started with an argument array.
- Electron's and Chromium's own security depends on staying current; Dependabot does not raise Electron majors by design (the owner chooses them).
- Whether the 24-hour update timer counts time the PC spends asleep was not verified.
